## Стратегия "мозг свежий vs мозг устал"

Главный принцип эффективности при твоём графике.

### На свежую голову (утро межвахты, выходные, отпуск)

- Изучение **новых концепций**
- Практические эксперименты, написание кода
- Чтение книг
- Создание Anki-карточек по новому материалу

### Когда устал (вечер после стройки, конец недели межвахты)

- Просмотр своих заметок
- Лёгкие YouTube-разборы по уже знакомому
- Anki — повторение

### На вахте (после 12-часовой смены)

- **Только Anki** — 10-20 минут, когда есть окно
- Иногда — перечитывание заметок с прошлой межвахты
- **Никаких** новых тем, новых книг, нового кода
- Цель вахты — не забыть пройденное, а не узнать новое

### Anki как multiplier

Если на каждой межвахте **создаёшь** карточки по пройденному, а на вахте **повторяешь** их — на следующей межвахте не тратишь время на "вспомнить, что было". Сразу идёшь дальше. Это даёт реальный +20% к усвоению при том же количестве часов.

**Артефакт:** `server-init.sh` в Git, работает на свежем VPS

### Тест юнита 6

1. Что делает `set -euo pipefail`? Зачем как первая строка?
2. Что такое идемпотентность? Пример НЕ-идемпотентного и фикс.
3. `$@` vs `$*` (с кавычками и без).
4. Как обработать ошибку и сделать cleanup (удалить tmp-файлы)?
5. Однострочник: пинговать IP из файла, выводить только недоступные.

<details><summary>Эталонные ответы</summary>

1. `-e` — exit при ошибке; `-u` — ошибка при использовании неинициализированной переменной; `-o pipefail` — exit code пайплайна = последней упавшей команды.
2. Идемпотентность = можно запускать многократно с тем же результатом. **НЕ:** `useradd deploy`. **Да:** `id deploy &>/dev/null || useradd deploy`.
3. `"$@"` — каждый аргумент отдельным словом. `"$*"` — склеены в одну строку. **Используй всегда `"$@"`**.
4. `TMPDIR=$(mktemp -d); trap 'rm -rf "$TMPDIR"' EXIT`
5. `while read -r ip; do ping -c1 -W1 "$ip" &>/dev/null || echo "$ip"; done < ips.txt`

</details>

**Артефакт:** репо с осмысленной историей, pre-commit hook

### Тест юнита 7

1. `git merge` vs `git rebase`? Когда что?
2. Случайный `git reset --hard`. Как восстановить?
3. Detached HEAD — что, чем опасно, как выйти?
4. 10 коммитов в feature, многие — фиксы опечаток. Как причесать перед merge?
5. `git pull` vs `git pull --rebase`. Что лучше в команде?

<details><summary>Эталонные ответы</summary>

1. Merge — merge-коммит, нелинейная история. Rebase — переписывает поверх, линейная. **Никогда не rebase ветки, на которые работают другие.**
2. `git reflog` → находишь SHA → `git reset --hard <SHA>`.
3. HEAD указывает на коммит, не на ветку. Опасно: коммиты не принадлежат ветке. Выход: `git switch -c new-branch`.
4. `git rebase -i HEAD~10` → `pick`/`squash`/`fixup`/`reword`/`drop`.
5. `pull --rebase` лучше в команде. В команде: `pull.rebase = true` глобально.

</details>

## Юнит 11 📺 — DNS глубже, CDN, email

**Тип нагрузки:** средний

**Теория (3ч):** 📺
- [ ] SPF, DKIM, DMARC
- [ ] CDN (Cloudflare)

**Практика (4ч):**
- [ ] Cloudflare на домен (уже подключён)
- [ ] **Здесь переключаемся на proxied** (оранжевое облачко)
- [ ] Кэширование, page rules
- [ ] (Опц.) Postfix + SendGrid/Mailgun free tier

### Тест юнита 11

1. Что делает SPF, как проверяется получателем?
2. DKIM vs SPF — принципиальная разница, что вместе закрывают?
3. Cloudflare proxied — плюсы и минусы.
4. A-запись 1.2.3.4, в CF proxied. Что покажет `dig` и почему?
5. DMARC `p=quarantine` vs `p=reject` — когда что?

<details><summary>Эталонные ответы</summary>

1. SPF — TXT-запись с разрешёнными отправителями. Получатель смотрит Return-Path → SPF домена → проверяет IP в списке.
2. SPF — **откуда** (IP). DKIM — **что контент не изменён**, подписан приватным ключом домена. Вместе: имеет право отправлять + контент не подделан. DMARC объединяет.
3. Плюсы: DDoS, кэш, WAF, скрытие реального IP. Минусы: CF видит весь HTTPS-трафик; не-HTTP порты ломаются.
4. Покажет **IP Cloudflare**. В proxied A-запись подменяется anycast-IP CF.
5. `quarantine` — в спам. `reject` — отклонить. Стратегия: `p=none` → `p=quarantine pct=10` → `p=reject`.

</details>
