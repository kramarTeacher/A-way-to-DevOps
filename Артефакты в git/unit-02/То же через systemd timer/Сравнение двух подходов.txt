Сравнение cron vs systemd timer

Аспект	                     Cron	                                 Systemd Timer
Простота настройки	     Очень простой синтаксис	                 Нужно 2 файла (.service + .timer)
Гибкость	             Базовые интервалы	                         Сложные календари, случайные задержки (RandomizedDelaySec)
Логирование	             Через syslog/email	                         Полная интеграция с journalctl (journalctl -u backup-etc.service)
Зависимости	             Нет контроля	                             Можно запускать после других сервисов (After=, Requires=), пример: "сначала смонтировать NFS, потом бэкап"
Пропущенные запуски	     Если система выключена — запуск теряется	 Persistent=true выполнит пропущенный запуск
Контроль состояния	     Нет	                                     systemctl status, systemctl list-timers
Мониторинг	             Только проверка логов	                     Встроенный тайминг, уведомления о пропусках

Вывод:
1. Cron — если нужен простой ежедневный бэкап, быстро и без лишних файлов.
2. Systemd timer — если важны: логи через journald, обработка пропущенных запусков, зависимость от других сервисов (например, сначала поднять сеть, потом бэкап на NFS).
Для бэкапа /etc cron более чем достаточно, но systemd timer даёт больше контроля в production-среде.
